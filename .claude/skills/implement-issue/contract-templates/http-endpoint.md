# 契約テンプレ: HTTP の受け口（`src/server.ts`）

対象: TradingView の webhook を受けるエンドポイントと、ヘルスチェックなどの補助のエンドポイント。受け口は **受け取って認証し、すぐ応答してから配信を始める**（TradingView は約 3 秒で打ち切り、再送しない）。

認証・本文の解釈の判定は HTTP から切り出して純関数として固定し（`pure-function.md`）、受け口のテストは実際にポート 0 で起動して `fetch` で叩くか、処理関数を直接呼ぶ。配信は偽の `Notifier` に差し替える。

## 記入項目

| 項目 | 書き方 |
|---|---|
| メソッド・パス | `POST /<path>`、`GET /healthz` など。それ以外のメソッド・パスの応答（404 / 405） |
| 認証 | TradingView はヘッダを付けられないので、共有シークレットを **本文の `secret`** またはクエリ / パスで受ける。比較は `crypto.timingSafeEqual`（長さ違いも同じ経路で拒否）。シークレットの値は環境変数から読む。不一致・欠落の応答（401 / 403）。**応答・ログにシークレット・受け取った値を出さない** |
| 本文 | `Content-Type` の扱い（TradingView は JSON なら `application/json`、それ以外は `text/plain`）、大きさの上限と超過時の応答（413）、文字コード |
| 応答の速さ | 配信を待たずに応答する（202 / 200）。配信の失敗は応答に反映しない（ログに残す） |
| 応答 | ステータス・本文の形。**受け取った本文・例外の本文を応答に出さない** |
| 異常系 | 壊れた本文・未知のチャネル ID・全経路の失敗のときの応答とログ。未処理の例外・Promise の拒否でプロセスを落とさない |
| ログ | 構造化ログ（JSON）。出す項目（受信時刻・経路ごとの成否・所要時間）/ 出さない項目（シークレット・トークン・送信先 ID・本文の全文） |
| 設定 | 読む環境変数（ポート・シークレット・設定ファイルのパス）の名前。実値はコード・docs に書かない |
| 設計との対応 | `docs/design.md` の節（あれば） |

## 記入テンプレ

```markdown
### `<METHOD> <path>` (`src/server.ts`) — 新規 / 改修

- auth: <シークレットの受け方、比較方法、不一致・欠落の応答>
- body: <Content-Type、上限、超過時の応答>
- response: <ステータス、本文の形>（配信を待たない: <はい>）
- 異常系: <壊れた本文 / 未知の ID / 全経路失敗の扱い>
- log: <出す項目 / 出さない項目>
- 設定: <環境変数の名前>
- 設計: docs/design.md <節>
- 改修の場合の差分:
  - 現契約 (コードとテストから抽出): <現状の入出力>
  - 変更点: <追加 / 変更した入出力>
  - 後方互換: TradingView 側のアラートの設定（URL・メッセージの形）を利用者が変える必要があるか
```

## 観察可能な AC への落とし方

ローカルで判定できる形（ポート 0 で起動したサーバーと偽の `Notifier`）を主にし、本番でしか判定できないものはデプロイ後の確認手順として明記する。

| 契約 | 観察可能な AC |
|---|---|
| 認証 | `secret なし / 違う値 / 長さ違いで 401、偽の Notifier が呼ばれない` |
| 秘密の非露出 | `401 の応答本文とログに送った secret の値が含まれない` |
| 本文の上限 | `上限 + 1 バイトで 413、偽の Notifier が呼ばれない` |
| 応答の速さ | `偽の Notifier が 5 秒待つとき、応答が 1 秒以内に返る` |
| 経路の独立 | `経路 A が例外を投げても経路 B に届く、応答は 202` |
| 反射しない | `壊れた本文を送った応答に本文の文字列が含まれない` |
| 本番 | デプロイ後、secret なしの POST が 401（`after-deploy`。URL は表示・記録しない） |

**書いてはいけない AC**: 「安全に受け付ける」「素早く応答する」（閾値が無い）。
