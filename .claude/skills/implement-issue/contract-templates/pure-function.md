# 契約テンプレ: 純関数（`src/alert.ts` のアラートの解釈・整形など）

対象: 副作用を持たず、同じ入力に対して常に同じ値を返す関数。例: `parseAlert`（webhook の本文 → `Alert`）、`extractSecret`、`formatText`（`Alert` → 通知の文面）、`truncate`、経路ごとのメッセージの組み立て（LINE の messages 配列など）、設定の検証。

通信（`fetch`）・現在時刻（`Date.now()` / `new Date()`）・乱数・環境変数（`process.env`）が混ざっている関数は、**それらを引数で受ける形に分けてから**、計算部分にこのテンプレを使う（通信する部分は `notifier.md`）。

## 記入項目

| 項目 | 書き方 | 例 |
|---|---|---|
| シグネチャ | 引数と戻り値の TypeScript の型（`src/types.ts` の型を使う） | `parseAlert(body: string, receivedAt: Date): Alert` |
| 入力の形 | 受け付ける形と、それ以外の扱い | JSON オブジェクト / プレーンテキスト / 壊れた JSON はテキスト扱い / 配列・null は テキスト扱い |
| 事後条件 (post) | 戻り値が満たす性質を **入力との関係** で書く | `secret` は戻り値のどこにも現れない、`message` は空でも string |
| 上限 | 長さ・件数の上限と、超えたときの扱い | 5000 文字（コードポイント）を超えたら末尾を `…` にして 5000 文字ちょうど |
| 文字 | サロゲートペア・改行・全角の扱い | 絵文字を途中で割らない |
| 異常値 | 型違い・空・欠落の扱い（例外を投げない / 投げる） | `channels` が数値なら undefined、空文字の `title` は undefined |
| 後方互換 | 既存のペイロード・文面の形を変えるか | `title` / `message` / `channels` / `secret` のキー名は変えない |
| 純粋性 | I/O・現在時刻・乱数・環境変数を触らない | 時刻は引数で受ける |
| 設計との対応 | `docs/design.md` の節（あれば） | 2 章 |

## 記入テンプレ

```markdown
### `<関数名>` (`<ファイルパス>`) — 新規 / 改修

- signature: `<型>`
- 入力の形: <受け付ける形 / それ以外の扱い>
- post:
  - <入力と戻り値の関係>
- 上限: <長さ・件数と超過時の扱い>
- 文字: <サロゲートペア・改行>
- 異常値: <型違い・空・欠落>
- purity: 副作用なし / 例外: <あれば>
- 設計: docs/design.md <節>
- 改修の場合の差分:
  - 現契約 (コードと既存テストから抽出): <現状の挙動>
  - 変更点: <追加 / 変更した挙動>
  - 後方互換: 呼び出し元 (grep -rn) と、利用者のアラートの設定・届く文面が変わるか
```

## 観察可能な AC への落とし方

契約 1 行 → vitest 1 本 → AC 1 行、の対応を保つ。入力は **架空の値**（架空の銘柄・価格）を使い、実際のアラートのペイロードは使わない。

| 契約 | 観察可能な AC |
|---|---|
| 秘密を残さない | `parseAlert('{"secret":"x","message":"m"}') の戻り値を JSON にしても "x" を含まない` |
| 壊れた JSON | `parseAlert('{"a":') が message = '{"a":' のテキスト扱い（例外を投げない）` |
| 上限 | `truncate('あ'.repeat(5001), 5000) が 5000 文字で末尾が …` |
| サロゲートペア | `truncate('😀'.repeat(5001), 5000) が 5000 コードポイントで孤立サロゲートを含まない` |
| 後方互換 | `旧形式のペイロード（テストに固定した架空の例）で同じ Alert になる` |

**書いてはいけない AC**: 「正しく解釈できる」「見やすい文面になる」。テストを通すために期待値を緩めるのも不可。
