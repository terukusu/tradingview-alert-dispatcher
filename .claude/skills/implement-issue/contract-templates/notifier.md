# 契約テンプレ: 通知の経路（`src/notifiers/<type>.ts`）

対象: `src/types.ts` の `Notifier` を実装する経路。例: `LineNotifier`（LINE Messaging API の push / multicast / broadcast）、将来の Slack・Discord・メールなど。

経路は **送るだけ** に責務を絞る。文面の組み立て（文字数の上限・分割）は純関数に切り出して `pure-function.md` で書き、待ち合わせ・失敗の切り分けは `src/dispatcher.ts` に任せる。テストは **偽の fetch** で行い、本物の API を呼ばない。

## 記入項目

| 項目 | 書き方 |
|---|---|
| 送り先 API | エンドポイント・メソッド・本文の形（公式ドキュメントの URL を併記） |
| 認証 | 資格情報の種類（チャネルアクセストークンなど）と読み方（設定には **環境変数の名前** だけを書き、値は環境変数から読む）。無いときの挙動（起動時に例外） |
| 設定 | 設定ファイルの `channels[]` に足す項目と既定値。旧形式との互換 |
| 送り分け | 送り先の数・種類で API を使い分ける規則（LINE: 0 件 = broadcast、1 件 = push、2 件以上 = multicast を 500 件ずつ） |
| 上限 | 外部 API の上限（LINE: text 5000 文字、multicast 500 宛先、1 リクエスト 5 メッセージ、料金プランの送信数）と、超えたときの扱い（切り詰め / 分割 / エラー） |
| 再試行と重複排除 | 再試行する応答（5xx・通信エラー・試行のタイムアウト）としない応答（429 を含む 4xx）、回数と待ち時間、冪等の鍵（LINE: `X-Line-Retry-Key` を再試行で同じ値にする、409 は送信済み） |
| タイムアウト・締め切り | 1 回の試行の上限と、送信全体（分割・再試行・待ちを含む）の締め切り（LINE: 試行 5 秒・全体 8 秒。停止時の待ちの上限 9 秒に収める） |
| 異常系 | 失敗時に投げる例外のメッセージ（ステータスと API の `message` だけ。**トークン・送信先 ID・本文を含めない**） |
| ログ | 出す項目 / 出さない項目（トークン・送信先 ID の実値・本文） |
| 設計との対応 | `docs/design.md` の節（あれば） |

## 記入テンプレ

```markdown
### `<クラス名>` (`src/notifiers/<type>.ts`) — 新規 / 改修

- API: <メソッド URL、本文の形、出典 URL>
- auth: <資格情報の種類、環境変数の名前（既定）、無いときの挙動>
- 設定: <channels[] の項目と既定値>
- 送り分け: <規則>
- 上限: <各上限と超過時の扱い>
- retry: <再試行する応答 / しない応答、回数、待ち時間、冪等の鍵>
- timeout: <1 回の試行のミリ秒> / 締め切り: <送信全体のミリ秒>
- 異常系: <例外のメッセージ（秘密・ID・本文を含めない）>
- log: <出す項目 / 出さない項目>
- 設計: docs/design.md <節>
- 改修の場合の差分:
  - 現契約 (コードとテストから抽出): <現状の挙動>
  - 変更点: <追加 / 変更した挙動>
  - 後方互換: 設定ファイルの旧形式が読めるか
```

## 観察可能な AC への落とし方

すべて偽の fetch で判定する。トークン・送信先 ID は架空の値（`U` + 架空の 32 桁の 16 進数など）を使う。

| 契約 | 観察可能な AC |
|---|---|
| 送り分け | `送り先 0 / 1 / 2 / 501 件で、偽の fetch が受けた URL が broadcast / push / multicast / multicast×2（500 + 1）` |
| 認証 | `Authorization が "Bearer <架空のトークン>"` / `環境変数が無いと構築時に例外（メッセージに値を含まない）` |
| 上限 | `本文 5001 文字で送った text が 5000 文字` |
| 再試行と冪等 | `500 → 200 で fetch が 2 回、2 回の X-Line-Retry-Key が同じ` / `400・429 で再試行しない` / `409 を成功扱い` |
| タイムアウト・通信エラー | `fetch が例外を投げると再試行し、尽きたら例外（メッセージにトークンを含まない）` |
| 送信全体の締め切り | `応答しない偽の fetch と短い締め切りで、締め切りの直後に失敗し、締め切りを過ぎた後に新しいリクエストを始めない` |
| 秘密の非露出 | `どの失敗でも例外メッセージにトークン・送信先 ID・本文が含まれない` |
| 実際の送信 | テスト用の送り先に届く（`not-observable`。ユーザーが行う手動確認の手順を書く） |

**書いてはいけない AC**: 「正しく届く」「エラーを適切に扱う」。本物の API を呼ぶテストも不可。
